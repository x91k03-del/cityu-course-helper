TRANSCRIPT INPUT / PARAMETER-ONLY QWEN / EXTERNAL OPTIMIZER
Three clearly fictional PDF transcripts reproduce the sample layout. The original student identity and record were not used in training.
Before training: 0/3 transcript inputs and 0/3 prompted inputs passed the strict objective-parameter contract; rejected answers never reached the solver.
Corrective training: 84 train, 8 validation, 8 separate record/weight export tests; three rank-8 QLoRA epochs. The six original failure prompts are familiar corrective retests.
After training: 3/3 paired examples have identical validated objective parameters and identical externally optimized paths. Separate parameter exports: 8/8. No repair or fallback.

Role boundary
PDF/text parsing is external. Qwen returns only reward_parameters, course_relations, penalty_weights and stream_reward_multiplier.
The program rejects profile fields, selected courses, timetables, paths, altered hard requirements, unknown relations and invalid weights.
The external exact DP chooses the remaining course placements. Independent enumeration checks all 64 allowed elective assignments. MILP and language-model planning are not called.

Limits and input handling
The maximum is within each supplied fixed source-backed completion context, not over every possible curriculum reallocation. Contexts differ between students; compare input formats within each case.
Saved Semester A/B evidence is repeated for simulation as authorised. 25 future credits have pending class details. These are curriculum plans, not confirmed registration timetables or official graduation certification.
Zero-credit P requirements count as passed and add zero credits. In-progress rows are not past passes. A star is retained; it alone never determines degree-credit eligibility. The fictional language row explicitly says Non-degree. Actual unclear credit treatment requires confirmation.
The eight scalar policy settings and 26 reviewed relations are familiar and fixed. Student state drives contextual rewards in external code; the model does not independently invent a different policy for each transcript.
The separate tests use new synthetic records and user weight combinations, with familiar formatting and policy. This is not unseen-policy or real-student outcome validation.

How to use
Run .\run_transcript_optimizer.cmd F (or N or M). The old natural-input launcher now uses this parameter-only interface.
For other PDFs/TXT files or ordinary student messages, the interface exports parameters and external facts. It does not fabricate a full-degree context when the supplied evidence is insufficient.
